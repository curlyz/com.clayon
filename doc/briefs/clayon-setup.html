part A · your steps on the Mac

A1 · approve Tailscale's network extension

  1. Tailscale is already open (menu bar icon). If macOS shows "System Extension Blocked" or asks to add a VPN configuration, click Allow and enter your password.
  2. If no prompt appears: System Settings → Privacy & Security → scroll to Security → click Allow next to Tailscale.
  3. Do not click "Log in" or sign in with Google or GitHub. That would join Tailscale's cloud. Part B points the app at your own Headscale.

A2 · turn on Remote Login for curlyz only

Option 1, System Settings (easiest):

  1. System Settings → General → Sharing.
  2. Turn Remote Login on.
  3. Click the ⓘ next to it → "Allow access for" → Only these users → keep only curlyz.
  4. Leave "Allow full disk access for remote users" off.

Option 2, terminal (in Claude Code, prefix each with !). systemsetup fails without Full Disk Access, so this uses launchctl:

sudo launchctl enable system/com.openssh.sshd
sudo launchctl bootstrap system /System/Library/LaunchDaemons/ssh.plist
sudo dseditgroup -o create -q com.apple.access_ssh
sudo dseditgroup -o edit -a curlyz -t user com.apple.access_ssh

The first two start SSH; the last two limit it to curlyz.

# step detail
B1 Deploy the headscale stack Headscale v0.29.4, plus a Caddy container that serves HTTPS on TCP 8443 with a Let's Encrypt certificate via Cloudflare DNS, plus a one-shot that creates the user curly and an API key. Headscale's relay STUN is on UDP 3478.

part C · Clayon wiring (I do this)

  1. Create a dedicated SSH key for Clayon. The public half goes in ~/.ssh/authorized_keys with from="100.64.0.0/10", so it only works from the private network. The private half becomes a Clayon secret.
  2. Turn on Clayon's Environments (Settings → Instance settings → Experimental).
  3. Add the SSH environment curly-mac: host curly-mac (its private address), user curlyz, the key, path /Users/curlyz/usr/antl. Press Test.

security

  • New public ports on the VPS: TCP 8443 (Headscale over HTTPS) and UDP 3478 (relay STUN). Both are Headscale's; Caddy serves only headscale.curly.ng.
  • Mac exposure: SSH is reachable only from the private network, by one key, and only from the VPS (policy B4). The Mac opens no port to the internet.
  • Why your own user: your OpenCode, Claude and Codex logins and your checkout live there; a separate user would have neither.
  • Code safety: each issue names its write scope, and nothing is committed or pushed without your approval.

troubleshooting

symptom check
Mac agent runs fail Is the Mac awake and online? Run /Applications/Tailscale.app/Contents/MacOS/Tailscale status; it must list the VPS node.
SSH refused Remote Login still on (System Settings → Sharing)? launchctl print system/com.openssh.sshd must succeed.
slow or relayed link Tailscale netcheck and Tailscale ping contabo-eu-vps6 show a direct path or the antl relay.
"opencode: command not found" The agent's adapter command must be the absolute path (nvm installs are not on SSH's PATH).

undo

  1. Disconnect the Mac: /Applications/Tailscale.app/Contents/MacOS/Tailscale down, or quit the app.
  2. Close SSH: turn Remote Login off, and remove the Clayon key line from ~/.ssh/authorized_keys.
  3. Remove the server side: delete the headscale stack in Dokploy, the headscale.curly.ng DNS record and the Cloudflare token "contabo-eu-vps6 headscale caddy dns-01".
